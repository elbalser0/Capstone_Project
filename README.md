## Seed data

The team database is already seeded with the fictional faculty data in
`Scripts/seed_data/` (generated by `Scripts/generate_faculty_data.py`). If you
connect with the shared `DATABASE_URL`, you don't need to load anything.

To seed a fresh or reset database (e.g. a new Neon branch or local Postgres):

```sh
pip install "psycopg[binary]"
python Scripts/load_seed_data.py   # reads DATABASE_URL from env or backend/.env
```

The loader refuses to run if the tables already have rows.

### Reset ID sequences after seeding

`dept_id`, `term_id`, `course_id` and `section_id` are identity columns, but the
seed data supplies explicit IDs, so their sequences still start at 1. Until
they're moved past the seeded IDs, the app's inserts into these tables fail
with duplicate-key errors. Run this once as the table owner (non-owner roles
get "permission denied"):

```sql
ALTER TABLE department ALTER COLUMN dept_id    RESTART WITH 5;
ALTER TABLE term       ALTER COLUMN term_id    RESTART WITH 13;
ALTER TABLE course     ALTER COLUMN course_id  RESTART WITH 56;
ALTER TABLE section    ALTER COLUMN section_id RESTART WITH 1116;
```

These numbers are each table's max ID + 1 for the current seed files. If you
regenerate the data, use the values `load_seed_data.py` prints instead.
